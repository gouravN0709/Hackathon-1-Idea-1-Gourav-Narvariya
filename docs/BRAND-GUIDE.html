Full guidelines

Complete brand system for the website and staff tools.

Version: 1.0 (repository audit, October 2026)
Audience: Designers, developers, copywriters, and contributors to the public website and staff tools.

These guidelines describe the brand as implemented in this Next.js project, plus recommendations where the codebase and a simplified marketing palette diverge. They are not a legal document and do not certify organic status, DOP membership, or historical facts unless the business owner confirms them.

Sections in this document: Quick reference, Full guidelines, Audit & gaps.

3.3 Contrast and pairing

Current behavior:

  • Light sections: text-primary or text-on-surface on surface / surface-container-*.
  • Dark sections (bg-primary): text-surface, text-surface-container-high for body.
  • Primary buttons: bg-primary-container + text-surface.
  • Global focus: outline: 2px solid primary-container with offset (globals.css).

Target: WCAG 2.2 Level AA for text and interactive components. Contrast has not been formally certified in this repo; run checks when changing tokens.

3.4 Colors to avoid introducing

  • Neon or high-saturation accents outside the amber/green family
  • Pure #000 body text on cream (use on-surface)
  • One-off hex in TSX when a semantic token exists

5. Photography and imagery

5.1 Direction (from asset usage)

Subjects reflected in public/images/ and site-config.ts:

  • Apple orchards, mist, limestone valley (gallery-valley, orchard stages)
  • Cellar barrels, txotx pour, cider production (txotx.jpg, orchard-cellar, menu gallery)

  • Guest experiences: orchard walks, harvest press, celebrations
  • Farm story portrait and family narrative (farm-portrait.jpg, our-farm section)

5.2 Technical treatment

  • Component: ResponsiveImage — Next.js Image, cover crop, required alt.
  • Hero: Low-opacity desaturated photo + green gradient (hero-section).
  • Cards: rounded-lg / rounded-xl, subtle shadow, optional hover scale with motion-safe.
  • Captions: Small label on bg-surface/80 + backdrop blur (gallery-section).
  • Aspect ratios: Mixed — portrait 4/5 in farm story, fixed heights in gallery grid, full-bleed heroes.

5.3 Accessibility and ethics

  • Write specific alt text (subject, place, action) as in existing config strings.
  • Do not state that imagery depicts verified real individuals unless the business confirms releases.
  • Avoid text baked into images for critical information.

6. Layout, spacing, and UI principles

6.1 Grid and width

  • Max content width: 1280px (SiteContainer, header inner wrapper).
  • Horizontal padding: px-margin-mobile → md:px-margin-tablet → lg:px-margin.
  • Section vertical rhythm: py-space-2xl common; hero uses min-h-[92vh].
  • Anchors: scroll-mt-24 on sections linked from nav (#story, #txotx, etc.).

6.2 Spacing tokens

From globals.css: space-xs through space-2xl, plus gutter, margin breakpoints. Prefer these over arbitrary Tailwind spacing when extending the system.

6.3 Radius and elevation

  • Buttons: rounded or rounded-lg.
  • Cards/panels: rounded-xl / rounded-2xl.
  • Shadows: soft green-tinted rgba shadows on header, footer, primary buttons — keep subtle.

6.4 Icons

  • Set: components/ui/icon.tsx — stroke SVGs (navigation, food, nature, service).
  • Size: Often h-4 w-4 to h-6 w-6 beside labels.
  • Do not mix unrelated icon libraries without a migration plan.

9. Brand voice and copywriting

9.1 Personality

Warm, clear, grounded, confident, welcoming — like a host explaining the valley, not a luxury resort brochure.

9.2 Vocabulary

Prefer: orchard, cellar, kupela, txotx, sagardoa, hearth, valley, season, share, gather, family farm, Aramaio.
Use carefully: organic, biodynamic, DOP, certified — only if owner-approved and legally accurate.
Avoid: “Exclusive luxury escape”, “once-in-a-lifetime”, fake countdown urgency, unsupported superlatives.

9.3 Patterns

  • Eyebrows: Chapter or category + optional middot separator (01 · Flora, Chapter I · The Guardians).
  • Headings: Sentence case or natural phrases; Newsreader does not need ALL CAPS.
  • CTAs: Verb-first, short — “Book a Visit”, “Explore the Txotx Ritual”, “View Directions & Shuttle Service”.
  • Booking honesty: Distinguish preview vs live (existing strings in booking-form.tsx — reuse tone for new messages).

9.4 Suggested examples (not on site — for future copy)

  • Slot unavailable: “That arrival time is full. Try another window or call us — we keep a few tables for walk-ins when we can.”
  • Txotx off-season: “Txotx runs January 15 – May 18. You can still book a cellar table or orchard walk outside the season.”

Label these as suggestions when adding to the product.

9.5 Accessibility in writing

  • Plain language for errors (“Choose an arrival time” vs codes).
  • Front-load important info in headings.
  • Do not rely on color alone for state (pair with text — already done for errors).

10. Accessibility and consistency

Target standard: WCAG 2.2 Level AA (goal, not a compliance certificate).

Area Current implementation
Skip link To #main, visible on focus
Focus Global :focus-visible; component rings on inputs and peer radios
Headings Logical H1 per page; sections use H2 via SectionHeading
Landmarks <header>, <main>, <footer>, nav with aria-label
Forms Labels, aria-describedby, error summaries with role="alert"
Motion prefers-reduced-motion reduces scroll and transitions
Touch min-h-11 on many buttons, inputs, accordion summaries
Images alt required on ResponsiveImage

When adding UI: Keep 44×44px minimum touch targets, maintain focus visibility, test keyboard path through modals/menus.

13. Do’s and don’ts

Do

  • Pull business strings from lib/site-config.ts.
  • Use semantic colors and type tokens from globals.css.
  • State booking preview/live status explicitly.
  • Write descriptive alt text.
  • Use SectionHeading, SiteContainer, ButtonLink for new marketing sections.

Don’t

  • Redesign completed guest pages unless tasked (see AGENTS.md).
  • Invent logo files, awards, or certification marks.
  • Commit secrets or env values to docs.
  • Use the brief hex palette in code without aligning tokens.
  • Imply WCAG compliance without testing.
